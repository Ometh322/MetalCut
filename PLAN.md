# MetalCut — платформа продажи металлорежущего инструмента

Демо-версия маркетплейса: витрина + поиск с фасетными фильтрами + AI-подбор, кабинеты покупателя и селлера, админка. Рынок — RU. Демо должно вырасти в продукт без переписывания.

---

## 1. Зафиксированные решения

| Область | Решение |
|---|---|
| Фронтенд + бэкенд | Next.js (App Router) + TypeScript, full-stack в одном репо |
| Архитектура | Бизнес-логика в `src/services/*` (вне роутов и экшенов); роуты — только транспорт. Сервисы пишутся так, чтобы могли переехать в NestJS-процесс без переписывания |
| БД | PostgreSQL + Prisma ORM |
| Атрибуты товаров | JSONB в `Product.attributes`, структура и валидация — схема атрибутов категории (свой формат схемы на каждую категорию) |
| Поиск | Этап 0: Postgres FTS (tsvector/trigram) + JSONB-фильтры. Этап 1 (после демо): Meilisearch за интерфейсом `SearchEngine`, добавление драйвера без рефакторинга |
| AI-слой | LLM по OpenAI-совместимому API за интерфейсом `QueryParser`; задача — конвертировать естественный запрос в фильтры по схеме категории. Для демо — заглушка/правила, провайдер подключается ключом |
| Каталог | `Category` (дерево + схема атрибутов) → `Product` (карточка, атрибуты JSONB) → `Offer` (цена/остаток/срок от селлера). Разделены с первого дня |
| Импорт | CSV/Excel с маппингом колонок на атрибуты категории; формат обмена спроектирован под будущую 1С (CommerceML = ещё один источник тех же сущностей) |
| Аутентификация | Демо: email+пароль, JWT в httpOnly-cookie (jose), роли `ADMIN / SELLER / CUSTOMER` |
| Язык / рынок | RU, один язык (i18n не закладываем в демо) |
| Оплата | Нет. Корзина → «заказ-заявка» со статусами (заготовка под реальный заказ) |

## 2. UI-референс: каталог и поиск — как в DNS (dns.com.ru)

Прямых скринов нет — ориентируемся на паттерны DNS-маркетплейса. Что копируем:

- **Левая колонка фильтров**: сворачиваемые группы; в длинных списках значений — встроенный поиск по значениям; числовые диапазоны — два инпута (от/до) + бегунок; чекбоксы с количеством товаров у значения.
- **Чипсы применённых фильтров** над списком + «Сбросить всё».
- **Тулбар списка**: количество найденных товаров, сортировка (популярность/цена/новизна), переключатель вид сетка/список.
- **Режим «список» (главный для B2B)**: горизонтальные строки с ключевыми характеристиками прямо в строке (диаметр, материал, покрытие, хвостовик) — как в DNS.
- **Пагинация** постраничная + «Показать ещё».
- Липкая (sticky) панель фильтров при скролле.
- Карточка товара: галерея, таблица характеристик (из атрибутов), блок офферов селлеров (цена/срок/остаток), кнопка в корзину.

Общий стиль: нейтральный светлый UI, акцентный цвет — оранжево-жёлтый DNS-типа или индустриальный синий; шрифт системный/Inter. Уточняется при сборке UI-кита.

## 3. Структура репозитория

```
prisma/                  — schema.prisma, seed, миграции
src/
  app/                   — только роуты (страницы и API)
    (shop)/              — витрина: /, /catalog/[...slug], /product/[slug], /cart, /checkout
    account/             — кабинет покупателя (заказы, повторный заказ)
    seller/              — кабинет селлера (товары, импорт, заказы)
    admin/               — админка (категории, схемы, модерация, селлеры)
    api/                 — REST-эндпоинты
  components/            — UI-компоненты (ui-kit + доменные)
  services/              — бизнес-логика: catalog, orders, offers, import, auth, search/, ai/
  lib/                   — db (prisma client), auth-утилиты, валидация
  data/                  — номенклатура: дерево категорий + схемы атрибутов (источник для seed и админки)
docker-compose.yml       — Postgres для локальной разработки
PLAN.md                  — этот файл (дополняется по мере работы)
```
